# Evidence Boundaries

This document records what the public skill pack does and does not claim.

| Skill / Playbook | Evidence the pattern requires | What it does not prove automatically |
|---|---|---|
| Reality-Grounded Acceptance | direct observation tied to a frozen requirement | that every untested requirement works |
| False-Green Detection | trace from PASS claim to supporting observation | that the implementation is globally correct |
| Production-Path Verification | real entry path plus naturally produced runtime facts | that alternate production paths are also correct |
| Artifact / Evidence Integrity | complete, consistent, candidate-linked artifacts | that the underlying capability itself works without reality evidence |
| Approval / Resume Verification | same work item, persisted pending action, original action resume | arbitrary workflow recovery |
| Process Lifecycle Verification | start, ready, control, disconnect, shutdown, cleanup observations | product-specific correctness beyond the scoped lifecycle |
| Dependency Truth Verification | explicit dependency state and requirement policy | capability success when a required dependency is absent |
| Candidate Identity Verification | immutable candidate identity linked to acceptance artifacts | correctness of the candidate without acceptance evidence |
| Environment vs Code Diagnosis | reproducible differential evidence | root cause from speculation alone |
| Frontend Runtime Truth | real interaction-to-runtime/read-back chain | full visual/accessibility correctness |
| External App Safe Startup | readiness, control, read-back, graceful close/cleanup | universal app-specific startup parameters |
| Final Candidate Freeze | frozen identity + complete acceptance artifact set | capability correctness beyond the evidence included |
| Independent Audit Adjudication | reproducible audit claim with classified outcome | that an auditor statement is true merely because it was reported |
